# Report Style Guide

## Purpose

Reports should turn public-source research into clear, evidence-backed output that another person can review. They should be objective, careful with conclusions, and transparent about limitations.

## Default Structure

Use this report structure unless a case requires a narrower export:

1. Case Summary
2. Scope and Objective
3. Methodology
4. Entities Reviewed
5. Key Findings
6. Confidence Summary
7. Evidence Table
8. Relationship Summary
9. Timeline
10. Recommendations
11. Limitations
12. Appendix

## Writing Rules

Use careful, evidence-based language:

- "Appears to"
- "Public sources indicate"
- "Based on available evidence"
- "This finding is supported by"
- "Confidence is high/medium/low because"

Avoid absolute claims unless authoritative evidence supports them. Reports should distinguish observed facts from analyst interpretation.

## Finding Examples

Good:

> The domain appears to have been registered recently. Confidence is medium because the registration date is supported by RDAP data, but ownership could not be independently confirmed.

Good:

> The website uses a contact email on an unrelated domain. This may be relevant in a fraud or vendor legitimacy review.

Avoid:

> This is definitely a scam domain.

## Required Context

Each exported report should include:

- Case scope and objective.
- Public-source methodology.
- Source URLs and capture timestamps.
- Confidence labels with rationale.
- Evidence references for key findings.
- Limitations and recommended next steps.
